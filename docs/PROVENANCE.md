# Data Provenance

## Purpose and Scope

This document describes the origin, collection, refinement, selection, transformation, and release process for the data distributed with the artifact accompanying the paper:

The public repository does not contain the complete raw phishing-kit corpus used in the paper. It contains a reduced evaluation subset of derived and sanitized analysis outputs, together with aggregate results and legitimate-site baseline measurements.

The public data is intended to support inspection and scaled-down evaluation of the released analysis pipeline. It is not expected to reproduce every full-corpus statistic reported in the paper.

## Dataset Overview

The study used the following principal data sources:

1. A corpus of phishing kits collected between July 2021 and March 2025.
2. Dynamic and static analysis results generated from the phishing kits.
3. Network and credential-submission measurements generated during controlled execution.
4. Legitimate authentication-portal measurements for the 15 most frequently targeted brands.
5. Human annotations and stored language-model responses used to evaluate the JavaScript behavior-classification procedure.
6. Derived backend-exposure and campaign-clustering results.

The complete refined phishing-kit corpus contains 4,409 kits. The public artifact contains derived analysis outputs for 100 selected kits rather than the underlying executable kits.

## Raw Phishing-Kit Collection

### Collection source

Candidate phishing-kit archives were collected from file and directory paths associated with phishing URLs obtained from the APWG eCrimeX feed.

Collection was performed from July 2021 through March 2025.

The collection process searched for publicly exposed compressed archives associated with the observed phishing infrastructure. Supported archive formats included ZIP, TAR, and 7z files.

The collection system:

1. visited paths associated with known phishing URLs;
2. inspected accessible directory listings;
3. searched exposed parent directories when appropriate; and
4. retrieved publicly accessible archive files that appeared to contain phishing-site resources.

This process produced 18,787 candidate compressed archives before refinement.

No victim credentials were intentionally collected. Controlled executions used synthetic input values generated by the analysis system.

### Collection boundaries

The collection was limited to resources that were externally accessible from the observed phishing infrastructure at collection time.

The collection process did not attempt to bypass authentication controls or exploit unrelated systems. Nevertheless, the collected archives may contain executable or security-sensitive material originally placed there by third parties.

The raw archives must therefore be treated as untrusted and potentially malicious.

## Dataset Refinement

The 18,787 candidate archives were refined to remove duplicates and unrelated software packages.

The refinement process included:

1. computing BLAKE2 hashes over archive contents;
2. incorporating directory structure and filenames into duplicate detection;
3. retaining a single representative when archive contents and structures matched;
4. comparing candidate archives against official releases of common software packages, including WordPress, to remove unrelated legitimate packages; and
5. inspecting available README files and package contents to determine whether each archive represented a phishing kit.

After refinement, 4,409 phishing kits remained in the research corpus.

Additional implementation details are described in Section 3 of the accompanying paper.

## Controlled Analysis Environment

The phishing kits were analyzed in an isolated environment operated by the researchers.

The environment included:

- an Apache HTTP server;
- support for PHP-based phishing backends;
- Chrome or Chromium controlled through Selenium and the Chrome DevTools Protocol;
- synthetic credential and form-input values;
- dynamic JavaScript instrumentation;
- network-request interception; and
- static inspection of HTML, JavaScript, and PHP files.

Global directory listing was disabled. Apache was configured to respect kit-provided `.htaccess` rules through `AllowOverride All`.

These settings were selected to approximate a conservative deployment environment and to avoid attributing exposure to permissive server defaults.

All phishing-kit execution and dynamic analysis were conducted inside an isolated VMware virtual machine with no Internet connectivity. The virtual machine's external network access was disabled throughout the experiments, while communication with the analysis environment's local Apache server was permitted. Consequently, email, Telegram, HTTP, and other exfiltration requests generated by the phishing kits could not reach third-party services or attacker-controlled infrastructure.

All form interactions used synthetic credential input values. No real credentials were entered, and no collected values were intentionally transmitted outside the isolated analysis environment.

## Generated Analysis Outputs

The controlled analysis produced two principal forms of per-kit output.

### General dynamic-analysis results

Files under:

```text
results/dynamic_analysis_blackwidow/analysis_results/
```

contain derived observations such as:

- detected forms and form fields;
- triggered JavaScript functions;
- DOM events and mutations;
- form-submission behavior;
- static server-side actions;
- inferred credential-exfiltration sinks; and
- selected network-request metadata.

### Network-analysis results

Files under:

```text
results/dynamic_analysis_blackwidow/analysis_results_network/
```

contain submission-centered network observations, including:

- request methods;
- request destinations;
- form-submission events;
- XHR and Fetch activity;
- selected request and response metadata; and
- credential-transmission classifications.

The public release contains 100 JSON files in each directory, representing paired outputs for 100 selected phishing kits.

## Public Evaluation Subset

### Purpose

The raw phishing-kit archives are not included in the public repository because they may contain:

- executable phishing components;
- stolen or victim-related information;
- attacker email addresses;
- Telegram bot tokens or chat identifiers;
- SMTP credentials;
- API credentials;
- live infrastructure references;
- Git repository metadata; and
- other operational or personally identifiable information.

Instead, the public artifact provides sanitized analysis outputs for 100 kits. This subset permits evaluators to exercise downstream analysis components without executing or redistributing the corresponding phishing kits.

### Subset-selection procedure

The 100-kit public subset was selected from the refined 4,409-kit corpus using the following procedure:

- Sampling frame: Canonicalized kits from `analysis_results` with a valid JSON result, a kit date between 2021 and 2025, and at least one observed form-submission transmission event.
- Selection method: Stratified, behavior-coverage-constrained deterministic selection with seeded tie-breaking.
- Random seed: `20260913`
- Stratification variables: Year; primary observed transmission method; exfiltration-channel evidence; OpSec/exposure evidence; and clustering diversity as a tie-breaker.
- Duplicate handling: Records were grouped by canonical kit identity. One result was retained per kit, prioritizing non-fallback dynamic analysis, then the number of observed submissions, forms, and visited URLs.

The subset is intended to cover the principal data formats and analysis behaviors needed to exercise the released software. It is not intended to be a statistically representative replacement for the complete corpus unless explicitly demonstrated.

Statistics computed from the public subset may therefore differ from the full-corpus results reported in the paper.

## Sanitization and Pseudonymization

Before public release, the selected analysis outputs are processed to remove or pseudonymize sensitive values.

The sanitization process covers, at minimum:

- email addresses;
- Telegram bot tokens;
- Telegram chat identifiers;
- SMTP usernames and passwords;
- API keys and access tokens;
- victim-provided values;
- IP addresses where disclosure is not necessary;
- live phishing or exfiltration URLs;
- local filesystem paths containing personal identifiers;
- Git author names and email addresses; and
- other credential-like strings detected by automated scanning.

## Legitimate-Site Baseline Data

Files under:

```text
results/dynamic_analysis_blackwidow/legit_results/
```

contain measurements collected from the official authentication portals of the 15 most frequently targeted brands identified in the phishing-kit corpus.

The legitimate portals were analyzed using the same general browser instrumentation used for the phishing-kit analysis. Semi-manual interaction was used when authentication portals employed anti-bot, SSO, or other mechanisms that prevented fully automated observation.

The released legitimate-site files contain derived interaction and HTTP-header measurements. They do not contain real account passwords.

Because legitimate websites change over time, these measurements represent the observed sites at the collection dates and may not reflect their current behavior.

## JavaScript Validation Data

The directory:

```text
data/js_validation/
```

contains a fixed evaluation set of 200 JavaScript functions and corresponding human labels.

The directory:

```text
results/js_validation/model_outputs/
```

contains stored responses from the evaluated language models.

These stored responses allow evaluators to recompute the released metrics without sending the functions to external model providers and without requiring paid API credentials.

Stored model outputs are point-in-time records. They may not be identical to responses generated by later versions of hosted models.

## Derived Results

The repository includes derived outputs such as:

```text
results/clustering/
results/js_validation/
results/probing/
results/statistics/
```

These files were generated from the complete corpus, the public subset, or the validation data as described in their directory-level README files.

Each result directory must state:

- its generating script;
- its input files;
- whether it represents the complete corpus or public subset;
- relevant software parameters;
- expected output files; and
- the paper sections, figures, or tables it supports.

Aggregate full-corpus results do not make the underlying raw corpus public and should not be interpreted as sufficient to reconstruct it.

## Known Limitations

The public release has the following limitations:

1. The raw phishing-kit archives are not publicly distributed.
2. The 100-kit subset does not reproduce every statistic obtained from the complete 4,409-kit corpus.
3. Sanitization may remove identifiers required to reproduce the full campaign-clustering result.
4. The public campaign-clustering run is intended to exercise the implementation and may produce no multi-kit campaigns after sanitization.
5. Legitimate authentication portals may have changed since measurement.
6. Stored hosted-model responses are tied to particular model versions and execution dates.
7. Full dynamic execution requires a more isolated environment than the default offline evaluation claims.
8. Aggregate full-corpus files may support inspection of reported results but do not constitute independent reproduction of the original experiments.

## Restricted Data Access

The complete phishing-kit corpus and unsanitized per-kit outputs are not publicly available.

Qualified researchers may request controlled access for legitimate research purposes.

## Ethical and Safety Considerations

The dataset contains material derived from malicious third-party infrastructure. It must be handled as security-sensitive research data.

Researchers must not:

- deploy the phishing kits;
- use the data to collect real credentials;
- contact or query exposed attacker-controlled credentials;
- interact with third-party systems without authorization;
- reactivate live exfiltration channels; or
- use the artifact for offensive or unlawful activity.
